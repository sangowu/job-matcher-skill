## 摘要

本版本在原有 Web Search 与静态/本机抓取之后增加一个默认关闭的远程隔离浏览器层。首个正式 Provider 是 Kernel；CI 和本地自动化测试只使用 Fake Provider，不产生云请求或费用。ATS 尚未接入，仍作为下一阶段独立验证的增强管道。

## 主要改动

- `browser_setup.py` 提供一次性 localhost 设置页，只绑定 `127.0.0.1`。API Key 连接测试成功后写入 Windows Credential Manager / macOS Keychain；`KERNEL_API_KEY` 可供无 UI 环境使用。
- `browser_provider.py` 隔离 Kernel SDK，并提供同契约 Fake Provider。远程会话使用 Kernel 的截图、点击、输入、按键、滚动和关闭接口，不使用 Playwright 控制远程浏览器。
- 真实 Kernel SDK 0.94.0 smoke test 修正了 `type_text` 的旧参数映射；适配器现使用当前的 `type_text(id, text=...)` 契约，并把可选依赖范围限定为已验证的 `0.94.x` API 系列。
- 同一 smoke test 发现远程 Linux 主机需要 X11 `Return` 键符号；适配器现自动把 Agent 常用的 `Enter/ENTER/Ctrl+Enter` 映射为 Kernel 可执行的 `Return` 形式。
- `browser_control.py` 在创建云会话前原子预留单轮预算；默认硬上限为并发 2、单站 3 页、单轮 10 会话、人工接管 10 分钟、估算费用 1 美元。
- `browser_workflow.py` 固定同站顺序翻页、跨页链接去重、页数封顶，并在人工操作、限流或失败状态下暂停而不继续点击。
- 子代理按角色请求模型：搜索 `gpt-5.6-luna/low`，CV 抽取 `gpt-5.6-terra/medium`，评估与视觉浏览 `gpt-5.6-terra/high`，默认隔离上下文。运行时不能满足覆盖时允许继承，但必须记录实际配置与 fallback。
- 运行指标 schema 升至 v2，新增子代理成功率、有效结果率、回退率、按实际模型/effort 分组的耗时，以及浏览器动作、会话、接管、限流和估算费用。

## 安全边界

- API Key 不进入 `config.json`、职位主表、报告或指标；环境变量仅读取，不回显。
- session ID、Live View URL、页面 URL、Cookie、键盘输入、截图、CV/JD 正文和异常全文均不进入指标。
- 默认关闭 stealth；禁止自动解验证码、模拟登录、代理轮换或绕过网站访问控制。
- 登录、验证或限流只暂停当前任务并请求人工接管；其他搜索与评估可以继续。

## 性能与质量证据

固定本地基准使用 15 个合成职位、2 次预热、10 次冷隔离迭代；每次都完成 15 merge、15 update、15 render。没有 Web Search、Kernel 或其他外部请求。

| 指标 | v2.2.0 p50 / p95 | v2.3.0 p50 / p95 | 变化 |
|---|---:|---:|---:|
| merge | 6.282 / 7.269 ms | 5.615 / 6.911 ms | -10.6% / -4.9% |
| update | 31.980 / 37.202 ms | 32.990 / 35.586 ms | +3.2% / -4.3% |
| render | 18.940 / 21.564 ms | 21.122 / 24.379 ms | +11.5% / +13.1% |
| 核心总耗时 | 55.741 / 64.107 ms | 60.666 / 64.604 ms | +8.8% / +0.8% |

确定性核心没有取得速度优化：总耗时 p50 增加 4.925 ms，p95 增加 0.497 ms；输出完整性没有退化。主要可见增量在 render 健康摘要扩展，后续版本应继续观察，不能把本版本描述成核心性能提升。

Fake Provider 每次迭代并发 2，完成 10 会话和 70 个含指标写入的动作：p50 56.763 ms、p95 73.022 ms、成功率 100%。该数字只衡量本地适配层与指标开销，不能代表真实 Kernel 网络延迟或招聘网站成功率。
