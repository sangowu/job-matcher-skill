## 摘要

本版本为职位搜索与评估流程增加了低依赖、隐私安全的运行监控，并把最近 7 天和 30 天的健康状态直接嵌入现有 HTML 求职报告。

每次 `merge` / `update` 都会自动追加一条 PII-safe 指标事件；每次生成 HTML 报告时，会自动计算两个时间窗口的健康快照。用户可以从报告顶部查看当前状态，并在全屏监控面板中检查关键指标与阈值告警，不需要部署 Prometheus、数据库或常驻服务。

## 本次更新

### 自动运行指标

- `data/metrics.jsonl` 自动记录搜索合并和评估写回的成功、失败、耗时与锁等待数据。
- 汇总缓存命中率、评估成功率、拒绝率、冲突率，以及命令和锁等待的 p50/p95/p99。
- 统计活跃评估批次、待处理任务和最旧积压时间。
- 提供 `healthy`、`degraded`、`no_data` 三种健康状态和可配置阈值。
- `scripts/summarize_metrics.py` 支持 Markdown、JSON 和适合自动化任务的非零退出码。

### HTML 健康面板

- 每次生成报告时自动计算最近 7 天和 30 天的静态健康快照。
- 报告顶部新增健康状态入口。
- 点击后显示全屏监控面板，包括 12 张关键指标卡和阈值告警列表。
- 支持 7/30 天切换、中英文界面、深色与浅色主题，以及 Escape 快捷关闭。
- 两个时间窗口共用一次指标文件读取和一次评估队列扫描，减少渲染开销。

### 可靠性与数据安全

- 指标采用字段白名单，不记录 CV/JD 正文、职位名称、公司名称、职位链接、`cv_hash`、`cp_hash`、`run_id` 或原始异常消息。
- 指标写入失败不会回滚职位搜索或评估结果。
- 监控摘要计算失败时，HTML 报告仍会正常生成，监控状态显示为 `unavailable`。
- 并发指标追加使用线程锁和短时跨进程文件锁，避免 JSONL 行互相覆盖。

### 修复

- `stats.new` 现在只表示当前 `merge` 新增的职位，不再统计主表中仍保留 `new` 状态的历史行。

## 使用方式

运行 Job Matcher 的方式保持不变：

> 这是我的简历 `D:\cv.pdf`，帮我找远程后端职位

HTML 报告生成后，点击顶部运行状态即可打开健康面板。也可以继续使用 CLI：

```text
python scripts/summarize_metrics.py --days 7 --format markdown
python scripts/summarize_metrics.py --days 30 --format json
python scripts/summarize_metrics.py --fail-on-breach
```

HTML 中展示的是报告生成时的静态快照；已经打开的旧报告不会轮询本地指标文件。重新生成报告后，快照才会更新。

## 兼容性与升级

本版本没有新增不兼容调用。现有 `merge_jobs.py`、`render_html.py` 和 Job Matcher 对话入口可以继续使用。

升级后不需要迁移 `jobs_table.json`。`data/metrics.jsonl` 会在第一次 `merge` 或 `update` 时自动创建；没有历史指标时，健康状态显示为 `no_data`。

## 已知限制

- HTML 监控是生成时静态快照，不会实时刷新，也不包含长期趋势图。
- 指标文件当前不会自动轮转或清理。
- 文件锁只协调同一文件系统上的进程，不提供跨主机一致性。
- 当前没有主动通知渠道；可以使用 `--fail-on-breach` 接入 Task Scheduler、cron 或 CI。

## 回滚说明

如需回滚代码，可切换到 `v2.0.0`。职位主表无需降级迁移；v2.0.0 会忽略新增的 `data/metrics.jsonl`。回滚后将失去自动指标记录、CLI 健康汇总和 HTML 健康面板，但不会影响已有职位数据。
