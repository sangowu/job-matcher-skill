# v2.3.0 Kernel 真实 Provider Smoke Test

日期：2026-08-25。环境：Windows 11、Python 3.13.5、Kernel Python SDK 0.94.0。

## 范围与安全边界

- 使用 2 个短生命周期远程会话，公开页面为 Cohere 的 Ashby 招聘列表与一条职位详情。
- 只执行连接、创建、截图、滚动、点击公开职位、地址栏输入、按键与关闭。
- 没有登录、提交申请、处理验证码、启用 stealth、代理轮换或访问非公开内容。
- 预算账本预留 2/10 会话和 0.20/1.00 美元估算额度；实际供应商账单以 Kernel 控制台为准。
- API Key 保存在 Windows Credential Manager。日志不含 API Key、Cookie、session ID、Live View URL、页面 URL、键盘输入或截图正文。

## 结果

| 检查 | 结果 | 证据/发现 |
|---|---|---|
| SDK 连接 | 通过 | `browsers.list()` 成功 |
| 创建与关闭 | 通过 | 两个会话均显式关闭 |
| 动态招聘列表截图 | 通过 | 可见 `Open Positions (147)`、筛选器、职位标题、地点、雇佣类型和工作模式 |
| 滚动 | 通过 | 从 Agentic Platform 区域滚动到 Internships / Marketing / Modeling |
| 点击职位详情 | 通过 | 打开 `Member of Technical Staff, Agentic Environments`，可见 Location、Employment Type、Remote、Department 与 JD 正文 |
| 文本输入 | 首次失败，修复后通过 | SDK 0.94.0 不接受旧的 `smooth=False`；改为当前 `type_text(id, text=...)` |
| 特殊按键 | 首次无导航，修复后通过 | Linux/X11 使用 `Return`；适配器把常见 `Enter` 形式归一化 |
| 验证/限流 | 未触发 | 两次会话均未出现 CAPTCHA、登录或 rate limit |

## 结论

真实 Kernel 闭环可完成“公开招聘列表 -> 视觉识别 -> 滚动 -> 职位详情 -> 地址导航 -> 清理”。Fake Provider/CI 没能发现的两个真实 SDK/OS 差异已经转为回归测试。该结果是小流量 observational smoke，不外推为所有 ATS/招聘站点的成功率或性能结论。
