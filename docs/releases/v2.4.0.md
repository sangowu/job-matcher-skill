## 摘要

本版本在原有 Web Search 和远程浏览器容错之后，增加默认关闭的公开 ATS 增强管道，并把职位标识、JD 交接、运行指标和版本同步纳入同一套可审计流程。ATS 仍是 Web Search 后的可选增强，不会替代 Web 发现，也不会把职位正文或用户数据写入指标。

## 主要改动

- 支持 Ashby、Greenhouse 和 Lever 的公开职位接口；维护独立 ATS board 标识库，但与 Web Search 共用职位主表和分析缓存。
- 引入稳定 `record_id` 和 Provider 强标识。不同强标识不会仅凭公司和标题弱键合并，降低职位误合并风险。
- ATS 已提供的 JD 可直接进入评估快照，避免再次抓取职位网页；没有正文时仍沿用原有浏览器容错阶梯。
- ATS HTML 正文会去除脚本和样式、转为纯文本并限制为 50,000 字符；主表、指标、同步状态和历史记录不保存原始 JD。
- 公共 ATS HTTP 请求默认支持 gzip，并同时限制压缩响应和解压后正文大小。
- 运行指标升级到 schema v5，以单个 PII-safe `run_id` 关联完整流程，记录开始、结束、搜索页、子代理使用量和指标完整性；缺少必要事件时健康状态为 `unknown`。
- 启动时可只读比较本地版本、Git commit 与 GitHub `main`。检查使用 24 小时缓存和 ETag，离线、限流或超时不会阻断职位搜索，也不会自动更新本地文件。

## 性能与质量证据

- 三组 Ashby、Greenhouse、Lever gzip A/B 保持 292 个职位、292 个含 JD 职位和 3 次请求完全一致；正文指纹全部匹配。中位网络传输量由 4,581,392 bytes 降至 948,090 bytes，减少 79.31%。网络耗时中位数观察到下降 5.37%，但公网波动较大，不作为稳定速度提升承诺。
- 小型三 Provider 质量样本完成 3 次公开 GET，归一化 291 个职位，并为抽样的 7/7 职位提供完整 JD。五维评估结果 7/7 通过契约；该样本只有一个直接匹配职位，不能代表市场整体准确率。
- Phase 5 离线回归的核心流程 p50/p95 为 53.541/60.395 ms，ATS Fake 归一化为 5.133/5.536 ms。相较前一快照，未证明性能提升，因此本版本不宣称核心流程加速。

## 安全与隐私边界

- ATS 默认关闭，只允许公开、受支持 Provider 的 GET 请求，并使用独立请求、分页和并发预算。
- CV、JD 正文、职位标题、URL、board token、API Key、Cookie、浏览器会话信息和异常全文不会进入公开基准或运行指标。
- 版本检查不上传 CV、JD 或搜索数据，不执行 `git pull`、切换分支或覆盖本地文件。
- CAPTCHA、登录、验证或网站限流仍需用户处理；系统不会自动绕过站点控制。

## 已知边界

- ATS 只是 Web Search 后的增强管道，覆盖度取决于 Web Search 是否发现公司及其官方 ATS board。
- 质量证据来自受控小样本和公开 Provider，不是对所有地区、公司或招聘网站的市场级精度保证。
- 没有 `.git` 的复制安装只能进行语义版本比较；精确文件同步状态需要 Git commit 信息。

## 验证
