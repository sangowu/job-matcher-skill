## 摘要

本版本将职位搜索与职位评估改为“并行计算、串行提交”。项目继续使用
`data/jobs_table.json` 作为唯一主表，不复制完整 B 表；每次评估只创建当前任务所需的最小快照，
并通过版本号和评估输入哈希进行条件回写。

这样既允许搜索与评估重叠执行，又避免两个 worker 同时覆盖主表、旧评估覆盖新 JD、完整职位表复制扩大敏感数据面等问题。

## 架构变化

### 修改前

- 搜索结果直接合并到单一 JSON 表。
- 评估更新缺少 run 级任务边界、版本检查和字段所有权校验。
- 写入不是完整的“锁 + 临时文件 + `fsync` + 原子替换”事务。
- 损坏 JSON 可能被当作空数据继续处理。
- 没有自动测试和跨平台 CI。

### 修改后

1. `merge` 在主表锁内完成去重和搜索字段更新。
2. `merge` 为待评估职位创建 `eval_run` 最小快照。
3. worker 可并行读取快照并计算，但不得直接写主表。
4. 编排者使用对应 `run_id` 调用 `update`。
5. `update` 校验任务归属、字段所有权、分数范围、记录版本和 JD 输入哈希。
6. 非评估输入发生变化时允许安全 rebase；评估输入变化时拒绝旧结果并返回冲突。
7. 所有任务完成或冲突后释放快照，仅保留不包含原始 CV 的运行历史。

## 不兼容变化与迁移

`scripts/merge_jobs.py update` 现在必须携带 `--run-id`。这是本版本升级为 `v2.0.0` 的主要原因。

### 旧调用方式

```text
python scripts/merge_jobs.py update --cv-hash <hash> --cp-hash <hash>
```

### 新调用方式

```text
# 1. 调用 merge，并读取输出中的 eval_run.run_id 和 eval_run.path
python scripts/merge_jobs.py merge --cv-hash <hash> --cp-hash <hash>

# 2. worker 读取 eval_run.path 中分配给自己的任务
# 3. 结果必须回传 dedup_key、base_record_version 和 jd_input_hash

# 4. 使用同一个 run_id 条件回写
python scripts/merge_jobs.py update --cv-hash <hash> --cp-hash <hash> --run-id <run_id>
```

升级时应同时更新编排提示词、脚本包装器或其他直接调用者。不要通过省略快照字段来兼容旧结果；这会绕过本版本新增的并发安全边界。

### 并发与数据安全场景

| 场景 | 样本 | 结果 | 验收标准 |
|---|---:|---:|---|
| 搜索与评估交错 | 100 个职位 | 100/100 搜索来源保留；100/100 评估安全 rebase；0 冲突 | 不丢搜索字段，不丢评分 |
| 并发主表写入 | 20 个 writer | 20/20 保留 | JSON 可解析，无锁文件或临时文件残留 |
| JD 输入发生变化 | 1 个过期结果 | 1/1 拒绝并报告冲突 | 旧评估不得覆盖新 JD |
| 非法/越权结果 | 2 个结果 | 2/2 拒绝 | 拒绝 `overall_score=999` 和修改搜索字段 |
| 部分提交与重试 | 2 个任务 | 首次提交成功，重复提交计为幂等，全部完成后释放 run | 不重复写入，不提前释放 |
| 主表 JSON 损坏 | 1 个场景 | 1/1 fail closed | 不得把损坏数据当作空表覆盖 |

本地耗时样本中，100 个职位交错更新测试约 0.07 秒，20 writer 并发测试约 0.93 秒。
这些数字用于回归比较，不是生产吞吐量或延迟 SLA；测试场景是确定性正确性验证，也不代表统计置信区间。

## 数据与安全影响

- 评估快照只保存完成任务所需字段，不复制完整主表，也不包含原始 CV。
- 评估只能更新 `jd_profile`、`match_score`、`verified`、`scored_from` 等评估所有字段。
- 主表更新使用跨进程锁和原子替换，降低进程竞争或中断造成 JSON 截断的风险。
- 完成后的运行历史只记录 run 级统计，不保留完整评估任务内容。

## 已知限制

- 当前文件锁只协调同一文件系统上的进程，不是跨主机分布式锁。
- 锁超时和 stale-lock 判断依赖本机时钟及配置值。
- JSON 主表适合当前单机 skill 场景；如果未来存在多主机写入，应迁移到支持事务和条件更新的数据库。
- 当前负载测试覆盖 20 个并发 writer 和 100 个交错职位，不等价于长时间 soak test。

## 回滚说明

1. 停止所有搜索和评估 worker，避免回滚期间继续写入。
2. 备份 `data/jobs_table.json` 和仍在执行的 `data/eval_runs/`。
3. 将代码回退到 `v1.0.0`。
4. 注意：`v1.0.0` 不理解 run-scoped 快照，未完成的 v2 评估结果不能继续回写。

由于回滚会移除冲突检测、字段所有权校验和原子写入保护，只建议在确认 v2 调用链无法修复时使用。
